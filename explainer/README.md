# Explainer kit

This kit makes a 3Blue1Brown-style explainer video from a script. It produces a 1080p30 MP4 (or a vertical 1080x1920 YouTube Short, see [Vertical Shorts](#vertical-shorts)) with a dark canvas, formulas that write themselves on in colour, a calm narrator, a soft synthesised score and subtitles.

The `make-3b1b` skill drives it. You can also run every step by hand. The method comes from Lurrobert's "3Blue1Brown-style explainer videos" spec (a gist). The term budget it sets is what makes the videos watchable. See [How to explain](#how-to-explain).

The kit is not part of the npm package. It lives in this repo for 2 reasons:

- its look comes from the library's design tokens (theme `mono-black` is the Modern Mono design)
- one versioned copy of the code outlives any working folder

## A project folder

Every tool runs inside a project folder:

| File | Written by | What it is |
|---|---|---|
| `script.json` | you | `{title, subtitle, scenes: [{id, chip, title, subtitle, sentences: [{text, say?}]}]}`. The spoken form is made from `text` by `ko_say.py`; write `say` only for what it cannot know (pauses, quotes read differently) |
| `scenes.js` | you | one draw function per scene id: `SCENES.<id> = (t, q) => {…}`. It is keyed to the timeline: `q.s(k)` is sentence k's start, `q.w('단어', k)` is the first spoken word containing a string at or after sentence k, and `q.wx(token, k, n)` is an exact token |
| `formulas.py` | you | `F = {id: (mathtext, colours)}`, where colours are theme names (`yellow`, `blue`, …) |
| `project.json` | you + `new_video.py` | slug, title, `commons` (image name → Wikimedia Commons title), `youtube` title and description, `theme`, `ui_commit`, `format` (`"short"`: vertical 1080x1920) or `size` (`[w, h]`) |
| `theme.json` | `new_video.py` | palette and fonts |
| `engine.js`, `video.html`, `fonts/`, `img/` | `new_video.py` | copied from this repo, or fetched |
| `timeline.json`, `narration.wav` | `narrate_*.py` | each sentence's start, end and duration, and estimated word times |
| `formulas.json` | `render_formulas.py` | glyph outlines per formula |
| `score.wav`, `score.json`, `mix.wav`, `out/` | `library_score.py` (or `score.py`, `music.py`), `export.py` | the score, the mix, the stills and the MP4; `out/cue_sheet.md`, `out/music_credits.txt` |

## Run it

```bash
K=~/2lab.ai/ui/explainer                       # this folder
python $K/tools/new_video.py ~/videos/euler --theme mono-black --from $K/examples/euler-identity
cd ~/videos/euler
ssh -f -N -L 19999:127.0.0.1:9999 blade-4090-ps   # soma-voice is reachable only through the Windows host
python $K/tools/narrate_soma.py                # one async job per scene; ~4 min per scene with padding
python $K/tools/render_formulas.py
python $K/tools/music.py && python $K/tools/export.py mix
python $K/tools/export.py stills 30 90 150     # look before rendering everything
python -m http.server                          # open video.html: play, scrub, jump to chapters
python $K/tools/export.py video --slices 12    # out/<slug>.mp4, about 3 minutes on an M-series Mac
```

Python needs `numpy matplotlib playwright pillow`. Add `edge-tts` for the fallback voice and `mlx-whisper` for QA. Install Chromium with `playwright install chromium`, and install `ffmpeg`.

Where no browser can start (a sandboxed agent session on macOS denies Chromium's Mach `bootstrap_check_in`), render
with `noderender/`: `npm install` there once, then run every tool with `PYTHONPATH=$K/noderender/shim` (and
`NODE_PATH=$K/noderender/node_modules`). The stand-in gives the tools a page that runs the project's engine.js,
docent.js and scenes.js on Node + Skia (`@napi-rs/canvas`), fonts from video.html's `@font-face`. Lint, gallery, stills
and the MP4 work unchanged; text antialiasing differs slightly from Chromium, so render a whole video with one of the two.
Without ssh to blade-4090, narrate with `SOMA_VOICE_FETCH=http` (one job per scene, its result URL cut at the digital
silence between turns).

## Vertical Shorts

A project renders at 1920x1080 unless its `project.json` says otherwise:

| project.json | Frame | Text stays inside |
|---|---|---|
| no `format`, no `size` (every older project) | 1920 x 1080 | the whole frame; subtitles 36 px, 44 px above the bottom edge |
| `"format": "short"` | 1080 x 1920, a YouTube Short | x 5-85 %, y 6-80 %: the Shorts player covers the bottom 20 % (title, channel) and the right 15 % (like, comment, share). Subtitles are 48 px, centred in that area, and sit on its bottom line |
| `"size": [w, h]` | any even size; an upright one gets the short's layout | as its format |

`python $K/tools/new_video.py <dir> --format short` writes the key. `engine.js` reads it in `loadAll()` (`FRAME`: `W`,
`H`, `safe`, `sub`, `subBottom`, `subTop`), resizes the canvas, and `video.html` keeps the player's shape;
`export.py` (viewport, stills, MP4, cover at 720x1280), `lint_scenes.py`, `sheets.py` and `noderender/` follow the
same size. `tools/frame.py` and `engine.js` `FORMATS` hold the same table; `tools/test_frame.py` checks that they agree
and that a project without the key keeps the 1080p layout.

Writing a Short (worked example: `examples/seneca-short`, Seneca's "life is not short", 58.7 s with cwon;
`new_video.py <dir> --from $K/examples/seneca-short` scaffolds it):

- 50 to 60 s: a question in the middle of the screen for the first 2 s, three to five pictures, the answer in one line
  from about 50 s. cwon speaks about 6.5 Korean characters a second with the gaps, so about 360 characters of `text`.
- Lay out from `FRAME.safe` (read it inside the draw functions: it is set after scenes.js loads). The picture area is
  roughly y 150-1280; the subtitle box grows up from y 1512.
- One scene without a `subtitle` keeps the opening and the cuts tight (a scene break costs `TAIL` + `LEAD`, 1.8 s).
- Text that is already on screen (the question, the answer) need not be repeated as a subtitle: set
  `"subtitles": "off"` and call `subtitle()` from scenes.js for the other sentences.

## Themes

| id | Look | Source |
|---|---|---|
| `mono-black` (default) | near-black canvas `#050505`, white type in Pretendard, colour only on the marks that mean something | the Modern Mono design: `src/core/tokens.json` `designs.modern-mono`, read when the project is made |
| `sketch` | flat light-blue paper `#bcd0e8`, black ink, purple handwritten keywords in Gaegu (OFL), red marks; subtitles stay in Pretendard | the book-docent page, measured from the Productive Peter reference (see Docent layer) |
| `3b1b` | the classic manim palette on `#101114`, Latin Modern / Noto Serif KR | built in |

Scenes name colours by role, not by value: `C.yellow`, `C.blue`, `C.green`, `C.track`, `C.grid`, `C.panel`, and `mix(C.green, 0.3)` for a tint.

In `mono-black`:

- yellow, green and red keep the design's semantic hues
- blue becomes the design's lavender accent
- teal and purple go white, as the mono palette does

So one colour per concept still holds where a concept appears as a mark.

## Docent layer

`engine/docent.js` draws book videos the way book-summary channels such as Productive Peter do (reference: "Life is
Short (How to Spend It Wisely)", 16:51, 148 words a minute, a new picture every 3.7 seconds). One stick figure lives
through the idea. Every idea gets a name on a board, an everyday picture and, when it helps, a picture equation. It
works on every theme; it looks its best on `sketch`.

Everything is ink drawn from the clock alone, with a slight fixed wobble so lines look hand-drawn, and every part takes
`p`, its draw-on progress from 0 to 1. Colours are roles: `C.ink` for lines, `C.key` for handwritten keywords, `C.red`
for cross-outs and circles (on mono-black they fall back to `C.text` and `C.blue`).

| Function | What it draws |
|---|---|
| `figure(x, y, {pose, face, s, t, walk, flip, look, tie, glasses, hair, hat, beard, mustache, outfit, accent, h, tag, crowd, p})` | stick figure; (x, y) between the feet, `s: 1` is about 340 px. Poses: stand wave point present think shrug cheer hold akimbo reach slump facepalm carry lift stop. Faces: smile happy neutral sad surprised worried angry think cool (= sunglasses, not 'calm') wink sleepy |
| `achilles`, `tortoise`, `crab`, `ant` | ready characters (helmet with a red crest, shell, crab, ant) |
| `cast(id, look)`, `person(id, x, y, o)` | one fixed look per person (hair, hat, outfit, accent colour, height, name); `person` draws it and returns anchors `{head, r, mouth, top, hands, box, dir}`. `tag: true` writes the name beside the chest |
| `say(who, text, o)`, `think(who, text, o)` | a speech / thought bubble placed beside the figure where it covers no face, figure, bubble or name tag, tail aimed at the mouth. Draw the figures first, then the bubbles |
| `animal(kind, x, y, {s, dir, p, tag})` | anteater cat dog bird fish mouse rabbit elephant whale turkey mammoth pig horse hen swan blackswan octopus bat bee turtle tick, each built from the features people name it by; returns anchors like `person` |
| `seated(id, x, y, o)` | a cast person in a wheelchair (chair, seated figure, wheel in front); returns the person's anchors |
| `docentGallery(kind)` | every cast look / animal / prop / hair style on one labelled sheet (`tools/gallery.py`) |
| `bubble(x, y, w, h, {kind: 'speech' \| 'thought', tail, text, body, p})` | speech or thought bubble; `body(x, y, w, h)` draws a small picture inside |
| `board`, `students`, `teach(term, {x, y, p})` | the named-idea classroom: presenter, board with the term, students from behind |
| `sign`, `signCard` | a figure holding the chapter sign. Set `TITLE_CARD = signCard` in scenes.js to use it as every scene's title card (engine.js calls `TITLE_CARD(sc, a, isFirst, lt)`) |
| `hand(str, x, y, {size, color, p})`, `handBlock` | handwritten text, written on left to right |
| `cross(x, y, w, h)`, `crossAt(cx, cy, w, h)`, `ring(cx, cy, rx, ry)`, `underline`, `eqSign`, `plusSign` | red X (`cross` from the top-left corner, `crossAt` from the centre), red circle (centre), underline, picture-equation signs |
| `scrollList(x, y, w, title, items, {mark, strike, p})` | a handwritten list on paper, items ringed or struck through |
| `bookCover`, `quote`, `chapterMap` | a drawn cover for a book without a cover image (a docent book shows its real covers, REFERENCE §4), a short quote, a progress map for long videos |
| `prop(name, x, y, s, {p, fill, t, time})` | (`time: [h, m]` fixes a clock's hands, default 10:10) 50+ everyday things: book openbook door opendoor ladder stairs mirror loop gear tree balance bulb clock calendar signpost house brain heart key lock box coin phone laptop monitor camera desk chair bench flag mountain sun cloud star eye magnifier puzzle trophy bridge globe note staff record phonograph doll pencil paper window fly rock puddle pawn cap map stadium ship whaleboat harpoon flask testtubes medal moon wind frame trolley lever bowl garage pcb fire barn crate rocket car mars factory moneybag satellite wheelchair barbell card seesaw notebook (`note` is a music note) … (`Object.keys(PROPS)`) |
| `shots(t, [[t0, draw], …])` | quick cuts: the last shot that has started is drawn, fading in over 0.22 s; `draw(t, lt)` gets the time since it started |
| `pop(t, t0)`, `dp(t, t0, d)` | pop-in scale with a small overshoot; draw-on progress |

A scene is a list of shots keyed to cues:

```js
TITLE_CARD = signCard;
SCENES.miu = (t, q) => shots(t, [
  [q.s(0), (t, lt) => teach('형식 체계', { p: dp(lt, 0, 1.2) })],
  [q.w('규칙', 3), (t, lt) => scrollList(700, 160, 520, '규칙 네 개', RULES, { p: dp(lt, 0, 3) })],
  [q.s(9), (t, lt) => { achilles(700, 900, { pose: 'think', face: 'worried', t });
                        bubble(820, 260, 520, 170, { tail: [760, 560], text: '조금만 더…', p: dp(lt, 0.3, 0.4) }); }],
]);
```

Worked example: `examples/geb` ('Gödel, Escher, Bach'; 30:31 once narrated with cwon). Its scenes.js starts with shared helpers
(`tiles`, `ruleCard`, `pqString`, `penrose`, `drawingHands`, `screenLoop`, `dolls`, `antBand`) and then one block per
chapter, about one shot per 4 seconds.

House rules for book videos: change the picture every 3 to 5 seconds; one subject per shot, at most one written word
(the chapter's named idea or the one number), at most one red mark, black ink only — the emphasis budget,
[REFERENCE.md](docent/REFERENCE.md) §0; show the picture before the name; keep the bottom 170 px clear (YouTube draws
its captions there); draw everything except the books' own covers: a docent book shows the real cover of the original
and of the Korean edition (REFERENCE §4); other artwork only when it is public domain.

Ink mode (project.json `"colour": false`, which `new_video.py` writes for every new sketch project or with `--docent`):
`figure`, `person`, `seated`, `animal`, `prop`, `crab` and `ant` paint every colour inside them as ink (lines, text) and
every fill that is not ink-dark as the page, so cast accents, outfits, animal coats and prop fills come out as unfilled
line art. Pass `colour: true` on a call when the colour is the meaning (a red heart). A project without the key (an
older video, a make-3b1b project) keeps its colours when its engine is refreshed. New docent projects also get
`"subtitles": "off"` and `"chip": false`; `export.py srt` writes the narration as `out/<slug>.srt` for the YouTube
caption track.

The craft rules, the shot recipes and the defect history live in `docent/`: [REFERENCE.md](docent/REFERENCE.md) (what
good looks like, with the check for each rule), [TEMPLATES.md](docent/TEMPLATES.md) (dialogue, three people, inner
voice, animal, timeline, …), [LESSONS.md](docent/LESSONS.md) (every defect found in a real video and what closed it),
[RESEARCH-LOG.md](docent/RESEARCH-LOG.md) (`research-skill` runs). Read them before a new book; update them after.

Every primitive reports what it drew in the current frame (`DOCENT`, `docentReport()`): half-drawn parts, faded
ghosts, ink under the subtitles or off the frame, empty bubbles, tails that point at no head, bubbles over faces or
name tags, people sharing a look, animals on the stick-figure rig — and the emphasis budget: the things on screen (each
top-level call; a crowd or a row of the same prop counts once), the written words (name tags included), the red marks
and any colour besides ink, purple and red. Three tools use it:

| Tool | Gate |
|---|---|
| `tools/timeline_draft.py` | a draft timeline from script.json (7.8 chars/s) so scenes, gallery and lint run before the voice is done |
| `tools/gallery.py cast animals props` | asset sheets: look at every one before any scene uses the asset |
| `tools/lint_scenes.py` | renders every shot at rest and fails (exit 1) on P0/P1 defects; writes `out/lint.md`, a still per bad frame and `out/lint_sheet*.jpg` (every rest frame, 60 per page) |
| `tools/title_check.py "<title>" --keyword <kw> --strict` | the title's form (hook first, ≤ 55, no format label) and one measured keyword in the title, on topic and over the demand bar (REFERENCE §10) |
| `tools/export.py cover` | `out/cover.jpg` (+ `cover_b`, `cover_c`) and `out/cover_check.jpg` at 1280 / 320 / 168 px; `WARNING cover:` lines for small text, more than 8 characters, a small subject, an edge cut or the time-stamp corner |

### Music: recorded beds, one per chapter

`tools/library_score.py` writes `score.wav` from `music/library.json`: human-composed tracks under CC BY (Lee Rosevere,
"Music for Podcasts" 3-6, made for spoken word; 63 tracks, 23 usable as beds). Every track was measured — percussive
share, attacks per second, energy in 1-4 kHz, dynamics, the audible body without the quiet intro and fade-out tail —
and only quiet, sparse tracks with no lead melody are marked `bed: true` and tagged with moods; a track with an
internal silence (≥ 1 s more than 20 dB under its own level: `library_score.py --measure` writes `holes`) is never a
bed — it would stop dead under the voice. Each chapter gets one
track in its mood family (`"mood"` in script.json); a chapter longer than its track chains a second one with a 4 s
cross-fade at a sentence gap, a sentence with `"music": "<mood>"` changes track exactly there, and a chapter break is a
3 s cross-fade centred on the title card. No track twice in a video while the 23 beds last (about 20 chapters; past
that one comes back, with a warning); tracks used by the last 10 videos cost more
(`~/.cache/2lab-explainer-music/history.json`). Each track is normalised to -20 LUFS and the bed gets a 3 dB dip
around 2.5 kHz. Output: `score.wav`, `score.json` (`kind: library`, so `export.py mix` ducks gently and lifts open
stretches +10.5 dB), `out/cue_sheet.md` and `out/music_credits.txt` — paste the credits into the YouTube description
and the audiobook notes; CC BY requires them. The audio (~540 MB) is downloaded from archive.org into
`~/.cache/2lab-explainer-music/library/` on first use (`--fetch` gets all of it; `--plan` writes only
`out/cue_plan.md`). The cue sheet and the credits are written after the render, so they always name the tracks in
`score.wav`.
Tests: `python -m unittest explainer/tools/test_library_score.py`.

Why not the alternatives (`music/library.json` "notes"): YouTube Audio Library tracks are licensed for YouTube only
(the M4A goes elsewhere); Scott Buckley's CC BY library has open Content ID claims; generated music cannot be judged
by ear in an unattended run. `tools/score.py` (generated General MIDI cues, fluidsynth + SoundFont) stays as the
offline fallback, `tools/music.py` (one D-major loop) for the math videos — the owner called the MIDI cues under a
documentary voice "garbage" (2026-11-10).

## Narration

`narrate_soma.py` speaks with the soma-voice API (Fish Speech S2 Pro) on blade-4090. The default voice is `cwon`.

- One async job per scene. The model loads once, then takes about 6 seconds per sentence.
- One turn per sentence, so subtitles and cues land on exact sentence starts.
- Filler padding. A bare sentence can start or stop with a clipped plosive, because the model begins and ends right at its edge. So each turn is sent as `아아. [pause] <sentence> [pause] 아아.`. `padcut.py` then cuts inside the two silences that `[pause]` leaves, with an 8 ms fade.
- Strict structure. A take is cut only when it has filler, gap, speech, gap, filler. A missing, merged or swallowed filler means re-synthesis, never a guess.
- Where to cut (padcut v3). A Korean sentence often ends in a soft decay: the vowel of 다 fades at −41 to −56 dB for 100 to 300 ms. It also often starts with a soft consonant (ㅎ ㅅ ㅈ). Both stay below the −40 dB voiced threshold.
  - v2 cut 80 ms after the last loud frame. It clipped the tail of 30 of 80 real takes by up to 330 ms. After the +13 dB loudness gain the clipped part would have been audible (−15 to −25 dB under the speech): you hear "…였습" with 다 gone.
  - v3 measures each gap's own noise floor (about −73 dB). It follows the sound that continues from the sentence, allowing dips of up to 60 ms, until that sound settles to the floor + 12 dB, then adds a short margin. A breath separated from the sentence by silence stays out. Sound still going at the middle of a gap means re-synthesis.
- Edge check. Every cut sentence must start and end on silence: its first and last 30 ms must be at least 30 dB under its speech. A cut that lands on sound is rejected. v2's clipped takes measured −16 to −25 dB; v3's measure −38 dB or lower. Whisper cannot do this check, because it completes a clipped "…였습" to "…였습니다" from context.
- Ear check. Structure alone cannot tell a missing filler from a short first or last word. So everything cut off (the whole prefix and the whole suffix) is transcribed with mlx-whisper, offline when the model is cached. It must be positively heard as filler (`아`, `아아`, …): empty output is a rejection. A failing take is re-synthesised with the next take seed, up to 3 rounds.
- Take records. Each cached take has `cache_voice/<key>.json`: text, take seed, the seed the server used, the raw take it was cut from, the cutter version and whether the ear check ran. A take is used only when its record matches the current cutter and check. Otherwise it is re-cut from its raw take, or re-synthesised.
- `--recut` re-cuts and re-checks every take from its recorded raw take, without the GPU. A take without a record (from an older version) is adopted only from a raw take of exactly the same text that passes both checks. Anything else is dropped and re-synthesised on the next run.
- Tests: `python -m unittest explainer/tools/test_padcut.py explainer/tools/test_ko_say.py explainer/tools/test_cwon_say.py` (synthetic takes, no audio files).
- Takes are cached by voice, take seed and text. A cutter change (the record's `cutter`, now `padcut-v3`) re-cuts every take from its raw take on the next run, without the GPU. `--redo scene:k` re-rolls one sentence. The API has no per-turn seed (turn i of a job gets seed s+i), so the seed the server actually used is recorded next to each take in `cache_voice/<key>.json`.
- The level is matched across sentences, and the whole track is set to −18.5 LUFS. The mix in `export.py` is tuned for that level.

blade-4090 runs WSL with mirrored networking. Port 9999 answers only on the Windows loopback, so open the SSH tunnel above, or set `SOMA_VOICE_URL`.

## Numbers and letters

The voice model never sees a digit, a symbol or a Latin letter. `ko_say.py` turns each sentence's `text` into Hangul, and both narrators refuse to start (before any GPU job) while anything else is left. Fish Speech has no Korean number normalisation of its own: digits reach its tokenizer as typed.

- Sino-Korean numbers by default: `1748년` → 천칠백사십팔 년, `10000` → 만, `0` → 영.
- Native numbers before counters that take them, up to 99: `2번` → 두 번, `20살` → 스무 살, `1시간` → 한 시간.
- Months 6 and 10 as spoken: `6월` → 유월, `10월` → 시월 (`6개월` stays 육 개월).
- Decimals: the point spelled 쩜, the fraction read digit by digit, every digit its own word: `2.71원` → 이 쩜 칠 일 원, `3.14159` → 삼 쩜 일 사 일 오 구.
- Fractions, signs and percent: `1/2` → 이분의 일, `-1` → 마이너스 일, `100%` → 백 퍼센트.
- Latin letters and words come from `project.json` `"say_lexicon"` (`{"e": "이", "i": "아이"}`). A letter missing from it is an error, never a guess.
- A sentence's own `say` still wins and is checked the same way.

Why 쩜, digit by digit. The National Institute of Korean Language has no rule for writing decimals in Hangul. Speakers read the fraction digit by digit and say the point as [쩜]; the institute gives 소수점 as [소ː수쩜]. Spelled `이 점 칠일 원`, the model read `이 점` as "this point" (or 이점, "advantage") and `칠일` as "the 7th". We tested five spellings on cwon: 5 sentences × 2 seeds, every take transcribed by whisper. A take passes only when the number is heard as a number.

| Spelling of 2.71원 | Heard as the number |
|---|---|
| `이 점 칠일 원` (the old `say`) | 7/10 — e.g. "2.7일원", "이점 칠일팔" |
| `이 점 칠 일 원` | 6/10 — e.g. "이 점이 O1이" |
| `이 쩜 칠 일 원` | **10/10** (used) |
| `이쩜칠일 원` | 9/10 — 3.14159 became "3.1415", 2 takes failed the pad cut |
| `2.71원` (raw digits) | 8/10 — 3.14159 became "314159" |

Tests: `python -m unittest explainer/tools/test_ko_say.py`.

## One-off voice clips

`cwon_say.py` is the same narration pipeline without a video project: text in, one file out.

```bash
python $K/tools/cwon_say.py "Claude가 GitHub에 PR 3개를 올렸어요. 회의는 3시에 시작해요." -o hello.wav \
    --lex '{"Claude": "클로드", "GitHub": "기터브", "PR": "피알", "회의": "훼이"}'
python $K/tools/cwon_say.py -f script.txt -o voice.mp3 --lex-file lexicon.json --dry-run   # spoken form only
```

- The text is split into sentences, and each sentence becomes one padded turn (`아아. [pause] … [pause] 아아.`). The filler is cut off again and must pass the ear check, exactly as in narration.
- Numbers go through `ko_say.py`. Every Latin word needs a Hangul pronunciation in the lexicon. A missing one stops the run before any GPU job, and the missing words are printed as a lexicon template to fill in.
- The lexicon may also respell Hangul words that the voice says wrongly. For example, cwon read 회의는 as "네이는"; `{"회의": "훼이"}` fixed it. The written text stays as it is.
- Edge check, then the hearing check. Every sentence must start and end on silence (see Narration). The file gets 0.15 s of silence at the start and 0.5 s at the end, so no player eats the last syllable. Then whisper transcribes each sentence on its own and compares it with the text. A sentence it did not hear the same way is marked `CHECK` and the word is named. Re-roll it with `--redo k`, or respell the word.
- Takes are cached in `<out>.cwon/`. A rerun only synthesises the sentences that changed. The output is set to −16 LUFS (`--lufs`).

## How to explain

These rules come from the spec's study of 3Blue1Brown lessons. Check them before you narrate:

1. Budget at least 150 spoken words per new term. A 6 to 8 minute video gets about 6 new terms.
2. Use at most 3 proper nouns.
3. Use one running example in every chapter. In the example, that is a dot walking a circle.
4. Show the picture before you say the name.
5. Ask the viewer one question per chapter, then answer it.
6. Build intuition first, then the formula in words, then at most one formula per idea.
7. Run a term audit in a fresh context before narration. List every word you would not use at dinner, then count words per term and proper nouns. Rewrite until it passes.
8. Fact-check historical claims against sources before narration.

## QA before anyone watches

- Run `audio_check.py`. It reports the transcript match per scene (number formatting is the usual difference), the sentence timing offsets and the diffs.
- Run `export.py stills` at every sentence, then `sheets.py`. Look for overlaps, missing cues (the page reports `missingCues()`) and text over subtitles.
- Measure loudness: the mix should sit near −15.5 LUFS with no clipping.
- Docent videos: `tools/gallery.py` sheets reviewed, `tools/lint_scenes.py` exits 0 and every `out/lint_sheet*.jpg` page looked at,
  `audio_check.py --sentences` all ok, `out/cue_sheet.md` shows one cue per section, `mix_check.py` 20-22 dB under the voice.
